# Phase 1 ও 2-এর UAT: চালানোর পরিকল্পনা (নভেম্বর 2026)

Phase 1 আর Phase 2-এর UAT একসঙ্গে চলবে। দুটি স্ক্রিপ্ট মেনে Claude নিজেই সব পরীক্ষকের ভূমিকায় কাজ করবে: প্রত্যেক কর্মকর্তা আর স্বেচ্ছাসেবক নিজের অ্যাকাউন্টে লগইন করে, যেমন মানুষ করত। স্ক্রিপ্ট দুটি: [PHASE_1_UAT_BN.md](PHASE_1_UAT_BN.md) (15টি দৃশ্য, ক থেকে ঢ) আর [PHASE_2_UAT_BN.md](PHASE_2_UAT_BN.md) (16টি দৃশ্য, ক থেকে ণ)। পাশাপাশি দেখতে কেমন লাগে আর ব্যবহার কতটা সহজ, তা নিয়ে উন্নতির প্রস্তাবও লেখা হবে, অগ্রাধিকার আর স্ক্রিনশটসহ। গেট পাস হলো কিনা, সেই সিদ্ধান্ত আপনার।

## ১. শুরুর আগে আপনার কাজ

UAT শুরু হবে খোলা কাজের PR মার্জ হওয়ার পর।

1. main checkout-এ `develop` pull করুন।
2. `pnpm db:migrate` চালান। এতে নতুন migration আর ছবির মাপের নতুন job-এর queue বসবে। তার পরপরই API restart করুন (চলমান API পুরোনো কোডে রেজিস্ট্রেশনের খসড়া পড়তে গিয়ে আটকে যেতে পারে)।
3. নতুন ডেমো ডেটা (স্ক্রিপ্টের নিয়ম; আপনার সিদ্ধান্ত লাগবে, নিচে ৭ নম্বর দেখুন): `pnpm db:reset`, তারপর `pnpm db:seed --set all` আর `pnpm db:load-locations`।
4. অ্যাপ চালু করুন (`pnpm dev`, অথবা Docker-এ `docker compose up`)। ঠিকানা: http://localhost:3000, API: http://localhost:4000।
5. আমাকে জানান যে সব প্রস্তুত। শুরুর আগে আমি `css_erp_dev`-এর একটি ব্যাকআপ (`pg_dump`) নেব। এটা শুধু পড়ে, কিছু বদলায় না।

## ২. কীভাবে চালাব

- অ্যাপের ভেতরের ব্রাউজারে http://localhost:3000 খুলে কাজ করব। কম্পিউটারের মাপে (1280 px) আর ফোনের মাপে (360 px) দুটোতেই।
- একটি ব্রাউজারে একসঙ্গে একজনই লগইন থাকতে পারে, তাই ভূমিকা বদলাতে লগআউট করে অন্যজনে লগইন করব। যে দৃশ্যে দুজন একসঙ্গে লাগে (যেমন নোটিফিকেশন), সেখানে একজনের কাজ শেষ করে অন্যজনে গিয়ে ফল দেখব।
- OTP সবসময় `123456`। সব তথ্য নমুনা: কাল্পনিক নাম, NID আর মোবাইল। আসল কারো তথ্য নয়।
- ডেটা লেখা হবে শুধু অ্যাপের মাধ্যমে। ডেটাবেস শুধু পড়ব, ফল মিলিয়ে দেখতে।
- বাগ পেলে লিখে রাখব, UAT চলার সময় ঠিক করব না। সব শেষে আপনি ঠিক করবেন কোনগুলো আগে ঠিক হবে।

## ৩. ডেটার পরিকল্পনা

| কী | কতগুলো | কীভাবে |
|---|---|---|
| স্বেচ্ছাসেবক | অন্তত 20 জন (ডেমোর বাইরে) | 5 জন পুরো নিবন্ধন পাতা দিয়ে (ফোনের মাপে, স্ক্রিনশটসহ)। বাকি 15 জন সেই একই পাতা যে API ডাকে, সেটা দিয়ে, প্রত্যেকে নিজের তথ্যে। সবার অনুমোদন অফিসের পাতা থেকে, RPM বা প্রজেক্ট এক্সিকিউটিভ হিসেবে। |
| উপকারভোগী | অন্তত 100 জন | 10টি আবেদন পুরো আবেদন-পাতা দিয়ে (NID খোঁজা, নিজে ভরা তথ্য, ছবি)। বাকিগুলো সেই একই API দিয়ে, প্রতিটি কোনো স্বেচ্ছাসেবকের নিজের অ্যাকাউন্ট থেকে। NID `1000002000` থেকে শুরু (ডেমোরগুলো `1000001000` থেকে)। |
| বিশেষ ঘটনা | প্রতিটি দৃশ্যের যত দরকার | একই পরিবারের দুজন, সম্ভাব্য ডুপ্লিকেট জোড়া, NID বা মোবাইল ছাড়া আবেদন, পাবলিক লিংকের আবেদন, ব্লক করা উপকারভোগী। এলাকা ঢাকা আর রংপুর দুই বিভাগে ছড়ানো, যাতে এলাকা অনুযায়ী দেখার নিয়ম পরীক্ষা হয়। |

সব আবেদন পাতা দিয়ে না করে বেশিরভাগ API দিয়ে করার কারণ সময়: 100টি আবেদন পাতা দিয়ে করলে কয়েক ঘণ্টা শুধু টাইপ করতেই যাবে। সার্ভারের নিয়ম আর অনুমতি এতেও একইভাবে পরীক্ষা হয়, কারণ পাতাগুলোও এই API-ই ডাকে। পাতার নিজের আচরণ দেখা হবে প্রথম 10টিতে আর দৃশ্যগুলোর ভেতরে।

## ৫. রিপোর্ট

- প্রতিটি দৃশ্যের জন্য একটি সারণি: ধাপ, যা হওয়ার কথা, যা হলো (পাস বা ফেল)। ফেল হলে বাগের বিবরণ থাকবে: কোন ধাপে, কী দেখা গেল, স্ক্রিনশট, সংশ্লিষ্ট নিয়ম (BR নম্বর)।
- বাগের তালিকা গুরুত্ব অনুযায়ী সাজানো: কাজ আটকে দেয়, ভুল ফল দেয়, অসুবিধা করে, আর ছোটখাটো।
- দেখতে কেমন আর ব্যবহার কতটা সহজ, তার উন্নতির প্রস্তাব আলাদা তালিকায়, অগ্রাধিকার আর স্ক্রিনশটসহ। এগুলো শুধু প্রস্তাব, কিছু বদলানো হবে না।
- অগ্রগতি একটি ফাইলে লেখা হবে, যাতে মাঝপথে থামলে নতুন সেশন সেখান থেকে চালাতে পারে।

## ৬. সময়ের আন্দাজ

ডেটা তৈরি প্রায় 1 ঘণ্টা, Phase 1 প্রায় 3–4 ঘণ্টা, Phase 2 প্রায় 4–5 ঘণ্টা, রিপোর্ট প্রায় 1 ঘণ্টা। একটানা না হয়ে কয়েক ভাগে হতে পারে।

## ৭. আপনার সিদ্ধান্ত (2026-11-23)

1. **শুরুর আগে নতুন ডেমো ডেটা:** হ্যাঁ। আপনি `pnpm db:reset`, `pnpm db:seed --set all` আর `pnpm db:load-locations` চালাবেন; তার আগে আমি `pg_dump` ব্যাকআপ নেব।
2. **বেশিরভাগ উপকারভোগী আর স্বেচ্ছাসেবক API দিয়ে:** হ্যাঁ। প্রথম 10টি আবেদন আর 5 জন স্বেচ্ছাসেবক পুরো পাতা দিয়ে, বাকিগুলো একই API দিয়ে, প্রত্যেকে নিজের অ্যাকাউন্ট থেকে।
3. **দুই Phase-এর মাঝে নতুন ডেটা:** না। Phase 1-এর হ্যান্ডওভার (দৃশ্য ছ) সবার শেষে হবে, তাই মাঝে আর ডেটা বসাতে হবে না।
